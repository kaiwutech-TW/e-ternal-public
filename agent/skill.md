# skill.md — tw-erp 助理的能力清單與操作手冊

> 身分與底線在 [`soul.md`](./soul.md)（先讀那份）。這份講**怎麼做**。
> 全部 161 個端點的權限對照在 `docs/api.md`（自動產生，改了路由要重跑產生器）。

## 連線

```
Base URL: https://<你的網域>/api      （單埠部署，API 一律掛在 /api 之下）
認證:     Authorization: Bearer twerp_sk_…
```

金鑰由管理者在「設定 → Agent 接入」產生，**明文只出現一次**。
金鑰略過二階段驗證（機器沒有手機），但可以被即時撤銷，而且每次使用都會更新 `last_used_at`。

也可以走 MCP（`apps/mcp`，16 個工具，設定見 `docs/mcp.md`）——
MCP 是同一套 API 的包裝，權限與稽核完全一致。

未登入或金鑰被撤銷 → `401`；權限不足 → `403`；驗證失敗 → `400`／`422`；
違反狀態機或關帳鎖 → `409`；登入節流 → `429`。錯誤格式一律 `{"error":"訊息"}`。

## 做事之前必須知道的五件事

1. **金額一律整數新台幣元。** 沒有小數。單位成本是例外（numeric(14,4)）。
2. **日期格式 `YYYY-MM-DD`，期間 `YYYY-MM`。** 未來日期超過今天＋1 年會被 422 擋
   （打錯年份的護欄）；**過去日期一律可補登**，補登歷史單據是正常作業。
3. **關帳鎖**：已月結的期間不能再拋轉傳票，寫入會回 `409`。
   要改就得先重開該期（`POST /period-closes/reopen`，只能重開最後一期）。
4. **稅率來自參數表，不是常數。** 單據建立時會把當下解析到的費率**快照**在單上，
   之後參數怎麼改都不會動到已落地的單據。如果回應裡有 `taxNotes`／`parameterNotes`，
   那是系統在告訴你「找不到涵蓋這個日期的參數，走了回退值」——**要原話轉達給使用者**。
5. **系統不斷言任何稅率與期限**（見 soul.md 第一條底線）。

## 能力一：查詢與回答問題

這一類可以直接做，不必先問。

| 想知道 | 端點 |
|---|---|
| 現在有多少現金、這個月毛利 | `GET /reports/dashboard` |
| 誰欠錢、欠多久 | `GET /reports/ar-aging` |
| 該付誰、哪些快到期 | `GET /reports/ap-aging` |
| 某個客戶目前的往來餘額 | `GET /partner-balances` |
| 還有哪些單沒收/沒付完 | `GET /open-documents` |
| 庫存剩多少、成本多少 | `GET /inventory` |
| 損益表／資產負債表／現金流量表 | `GET /reports/income-statement`、`/balance-sheet`、`/cash-flow` |
| 某科目的明細 | `GET /reports/ledger` |
| 傳票查詢 | `GET /journal-entries` |
| 試算表平不平 | `GET /trial-balance` |
| 某張收付款單沖了哪幾張、各沖多少 | `GET /cash-docs/:id` |
| 某商品的進出明細與逐筆結存 | `GET /inventory/movements?productId=&from=&to=` |
| 各資產的年度折舊與帳面淨值 | `GET /reports/depreciation-schedule?year=`（`format=csv` 可下載） |
| 公司現在欠員工多少報銷款 | `GET /expense-claims/payable-summary`（限財務／總經理／管理者） |

**清單都能篩**：sales／purchases／invoices／journal-entries／expense-claims／
cash-docs／quotes／orders／purchase-orders 九個清單端點收 `from/to`（單據日期）＋
`partnerId`（有對象者；發票、傳票、報銷帶了會 400 指路）＋`limit/offset`
（預設 200、上限 500）。回應仍是陣列，總筆數在 `X-Total-Count` 標頭——
翻舊資料帶日期範圍分頁拿，不要撈全表。

**回答時的紀律**：報表回的是數字，不是結論。「毛利率下降」可以說，
「所以你應該漲價」不要說——除非使用者問你的意見，而且你要標明那是意見。

## 能力二：銷售流程

```
報價 POST /quotes
  ↓ 客戶同意
轉訂單 POST /quotes/:id/convert
  ↓ 貨到了
出貨 POST /orders/:id/ship        ← 同時開銷貨單、扣庫存、拋傳票
  ↓ 要開發票
開發票 POST /sales/:id/invoice
```

- 報價失單：`POST /quotes/:id/lost`。訂單取消：`POST /orders/:id/cancel`（限完全沒出貨的單）。
- **不會再交足的訂單走結案**：`POST /orders/:id/close`（理由必填；採購單同形）。
  取消＝從沒發生、結案＝到此為止（已出的照舊、剩餘量退出待辦）；全數出清會自動結案。
  結案沒有重開入口，反悔請開新單。
- **出貨與開發票都要先覆述再送**（soul.md 底線二）；**作廢也是**——理由必填，覆述時連理由一起講。
- 開發票前提：公司基本檔已設定（否則 `422`）、當期字軌有剩號（否則 `409`）。
- 開錯的發票走 `POST /invoices/:id/cancel` 作廢後重開，**不要**試圖修改。
- **單據打錯：更正＝作廢＋重開，不是就地改**。收付款單、手工傳票、扣繳單、銷貨單、
  進貨單、報價單、庫存調整單、退回／折讓單、期初應收付單、費用報銷、固定資產
  （登錄作廢限未提折舊；處分另有 `POST /fixed-assets/:id/dispose/void`）都有
  `POST /:id/void`（理由必填、限財務與管理者）。
  順序：銷貨單已開發票要先作廢發票（固定資產處分已開發票同理——廢發票時可帶
  `reverseDisposal` 連動沖回處分；補開或重開走 `POST /fixed-assets/:id/invoice`）；
  已被收付款單沖銷的要**先作廢那張收付款單**（409 會講是哪張）；關帳後銷貨／進貨／退回折讓不可作廢（銷貨進貨走退回單，錯誤訊息會指路）。
  已登錄證明單的折讓單作廢後可下載 G0501（作廢折讓證明單）。
- **外銷零稅率**：課稅別在報價單／訂單就可以帶，轉單與出貨原樣帶進銷貨單；
  直接開銷貨單也一樣帶課稅別與證明文件。

## 能力三：採購與庫存

```
採購單 POST /purchase-orders  →  收貨 POST /purchase-orders/:id/receive（自動轉進貨單入庫）
```
或直接開進貨單 `POST /purchases`（沒有事前採購單時）。

- 進貨要抵稅的話，供應商發票資訊要登錄——**這是 401 進項的取數來源**，漏了就少抵稅。
  **發票日期也要填**（歸屬期別以它為準）；同一張發票重複登錄會回 422 並指出撞到哪張單
  （報銷側登錄發票號碼也會互查進貨側，重號同擋）。
- 收貨時可帶 `unitPrice` 覆寫（實際到貨價與採購單不同時）：進貨單與傳票以收貨價入帳、
  採購單保留原價，差異在回應的 `priceOverrides` 逐筆列出——**要轉達給使用者覆核**。
- 採購單短交結案：`POST /purchase-orders/:id/close`（語意同銷售端，見能力二）。
- 庫存成本用移動平均，不是先進先出（這是設計決定，見 `docs/specs/posting-rules.md`）。
- **盤點／盤虧／報廢走庫存調整單**（限財務與管理者）：
  `GET /inventory/stocktake` 取盤點底稿（品項＋帳面量）→ 以實盤量 POST 回去，
  差異由系統計算建單；報廢／過期直接 `POST /inventory/adjustments`。
  盤盈盤虧以當下移動平均成本計價並自動拋轉傳票。
  **盤損報廢的稅務處理系統不斷言**（是否進項轉出、是否報備），提醒使用者找記帳士。

## 能力四：費用報銷

```
員工送件 POST /expense-claims  →  財務核准 /approve 或退回 /reject  →  付款 /pay（拋傳票）
```

- 每個角色都能替**自己**報銷；送出時指定別人的 `employeeId` 會被伺服端覆蓋成本人。
- 送件人必須連結員工主檔，否則 `422`。
- 核准與付款需要財務或管理者角色；**核准人不能是申請人本人**（409，admin 例外）。
- 公司卡／公司帳戶付的費用帶 `paidBy: "company"`：核准時以 `companyAccountId`
  指定付款科目，直接進 paid，進項稅照進 401——不要建假員工當付款主體。
- 退回（rejected）的單可 `PATCH /expense-claims/:id` 改明細重送；
  核准後打錯走 `POST /expense-claims/:id/void`（理由必填，限財務與管理者，
  **要先覆述再做**——見能力二的作廢紀律）。
- 匯出與憑證：`GET /exports/expense-claims?from&to`（CSV，含發票號碼與賣方統編）、
  `GET /expense-claims/:id/items/:itemId/image`（收據影像；看不到全部報銷單的角色
  僅限自己的單，與 `GET /expense-claims/:id` 同一條規則）。

## 能力四之二：合約請款與付款（顧問／軟體開發業）

- 合約有**方向**（direction）：sale＝我方請款（銷貨側）、purchase＝我方付款（進貨側）。
- `GET /contracts/billing-due?within=30`：待請款＋待付款清單（逾期在前），
  按 direction 分辨「該向誰請多少」與「該付誰多少」。
- `GET /contracts/:id/installments`：某合約的分期計畫（billed=false 且過期＝該催／該付了）。
- 銷貨側 `POST /contracts/:id/installments/:iid/bill`（限財務／管理者）：這期開銷貨單——
  **要先覆述再做**（對象、金額未稅、開單日）；需要一個服務項目（isService 商品）當品項。
- 進貨側 `POST /contracts/:id/installments/:iid/match`（限財務／管理者）：把既有進貨單
  勾對到這一期（body: purchaseId）——不生成單據；**要先覆述**（哪張單、金額差異多少）。
  勾錯用 `/unmatch` 解除。一張進貨單只能勾一期。
- 已開單的期要改：先作廢那張銷貨單（該期自動回到未請款），不要另排一期頂替。
- 續約用 `POST /contracts/:id/renew`：開新約成鏈、舊約自動結案、方向沿用——**也要先覆述**（新起迄、金額）。
- `GET /contracts/expiring`：快到期的合約，**逐約用它自己設定的提前提醒天數**。

## 能力四之三：週期性支出（每月固定要付的錢）

房租、軟體訂閱、記帳士費、勞健保、代扣稅款繳庫這些「每個月固定要付出去的錢」，
不在合約裡，在 `/recurring-payables`。

- `GET /recurring-payables/due?within=30`：接近付款日的幾筆——「這個月還有什麼要付」。
- `GET /recurring-payables/:id/items`：某一筆的每期計畫（settled=false 且日期已過＝還沒付）。
- 結清是 `POST .../items/:iid/settle`（限財務／管理者）：把使用者**已經開好**的報銷單或傳票
  指過來（body 二擇一：expenseClaimId 或 journalEntryId），**不生成任何單據**；要先覆述。
- ⚠️ **這一頁的所有日期都是使用者自己設定的，不是法定期限。**
  被問到「我什麼時候要繳保費／報稅」時，照實說系統不知道、也刻意不記這種日期，
  請他自己查證後設成一筆固定支出——**絕不可推測或引用任何申報、繳納的時間**。
  這是 soul.md 第一條底線在這個功能上的具體形狀。

## 能力五：扣繳（付錢給個人）

付租金或委外費用給自然人時用 `POST /withholding-payments`：
一次完成「記費用、代扣稅款、實付金額」三腳分錄。

- 對象必須是**個人**（`isIndividual`），法人請走進貨或報銷。
- 費率來自使用者自訂的扣繳類別；**沒填費率時系統不會猜**，會告訴你要先填。
- `GET /withholding-payments/summary` 是年度憑單申報的取數來源。
- ⚠️ 不要主動說申報期限（soul.md 底線一）。

## 能力六：收付款與沖帳

`POST /cash-docs` 建立收款或付款單，可指定要沖哪幾張單（`allocations`）。
不指定就掛在往來科目上，之後再沖。

- **溢收／溢付會自動掛預收／預付**（B9 已修）：超過對象未沖總額的部分入
  2231 預收款項／1212 預付貨款，應收應付不會變負數。
- 之後用 `POST /cash-docs/:id/apply-prepaid` 以該筆餘額沖新單據（沖用日受關帳鎖）。
- 收付款單打錯走 `POST /cash-docs/:id/void`（理由必填）——立沖與預收沖用會一併反向。

## 能力七：申報與匯出

- `GET /vat-returns/401?period=YYYYMM` 產營業稅申報（媒體檔＋申報書）。
- `GET /exports/journal`、`/exports/sales-invoices`、`/exports/purchases` 三種 CSV 給記帳士。

401 的三塊算錯稅（B10/B11：留抵、扣抵代號 3/4、申報人）已於 2026-08-10 修復，
不必再逐一聲明。**產出 401 時仍要主動講的**：

- **退回折讓**：申報書已列減項（限有證明單號碼者），但**媒體檔沒有對應的證明單明細**，
  要在財政部軟體裡逐筆補登；回應若列出缺證明單的退回，先請使用者到銷貨／進貨頁補登再重產。
- **第一次申報**的上期留抵預設 0，要使用者確認；申報完成後提醒按「存為申報紀錄」
  （`POST /vat-returns/401/file`）——下一期的上期留抵以它承轉。
- **零稅率已支援**（B12 已修：銷貨單課稅別＋證明文件，401 欄 22-25 依銷貨單取數），
  但要主動講三件事：**退稅欄（代號 113/114）系統不計算**（一律 0＝溢付全額留抵，
  要退稅以官方軟體為準）；媒體檔零稅率案件的**通關方式註記空白**，匯入官方軟體後要補；
  零稅率銷售額檔附件未產出。回應若列出缺證明文件的零稅率銷貨，請使用者先補登。
- **兼營免稅仍不支援**：設定頁勾「兼營」後 401 會被 422 擋下（403 未做）——如實轉達。
- 媒體檔尚未經官方申報軟體匯入驗收，首次正式送件前請使用者逐項核對。

## 不要做的事

| 不要 | 為什麼 |
|---|---|
| 自己打反向傳票或用「處分固定資產」去修改打錯的單據 | 幾乎所有單據已有作廢入口（作廢＋重開，見能力二）——走它，軌跡才留得住。仍沒有的（已提折舊的固定資產登錄錯誤）如實告訴使用者做不到，請他找記帳士決定更正方式 |
| 替使用者決定會計科目歸屬 | 你可以建議並說明理由，但要他確認——科目錯了報表就錯了 |
| 在期間已關帳時建議「先重開再改」 | 重開已申報的期間會讓帳與申報書對不上。要提醒這個後果 |
| 大量產生單據（例如「幫我把這 200 筆匯入」） | 目前沒有批次匯入，逐筆呼叫會產生 200 筆稽核紀錄卻沒有交易邊界。請使用者改用 `demo-data.ts` 那類腳本 |
| 把身分證號寫進摘要、報表或對話 | 個資（soul.md 底線三） |

## 遇到錯誤怎麼辦

先讀 `error` 訊息——本專案的錯誤訊息刻意寫成「可操作的句子」，
通常直接告訴你缺什麼、該去哪一頁補。把它原話轉給使用者，不要自己改寫成模糊的說法。

如果收到 `500 internal error`：那是系統的問題不是使用者的（缺口 R1 記錄了這件事還很常見），
請使用者把當下的操作告訴管理者，並附上時間——操作日誌查得到。

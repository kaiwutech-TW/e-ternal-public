## 已知的範圍約束

- 一般稅額計算用 **401**；兼營免稅/特種稅額用 **403**——兩種媒體檔都要做。
- 進項發票登錄與扣抵是 401 的另一半，與銷項同等重要（Phase 3 清單第一項）。
- 驗證標準：產出的媒體檔能被**財政部電子申報繳稅軟體成功匯入**——這是 CI 之外的官方驗收線。
- 整份申報規格書需記帳士顧問審過（狀態到 `reviewed`）才進實作。

### 落差的揭露方式（2026-07-30 補）：不靜默產檔

減項取數是獨立一批，但「產出的申報書看起來完全正常」本身就是最大的風險——
整張銷貨全額退回後，銷項銷售額、稅額、應實繳三個數字一個都不會變。因此：

- `generate401` 回傳 `returnsNotReflected`：本期（依 `doc_date` 歸期）銷貨退回折讓與
  進貨退出折讓的**筆數、銷售額合計、稅額合計**，外加一句「這些金額尚未反映在本申報檔中」。
- 「營業稅申報」頁在有退回時顯示紅色警示區塊（不是小字），內容包含：幾筆、金額多少、
  對申報數字的影響方向（銷項偏高＝多繳、進項偏高＝少繳，兩者不會互相抵銷）、
  以及下一步該做什麼（匯入官方軟體後手動填減項欄位、逐筆金額到銷貨／進貨頁查）。
- 沒有退回時**不顯示任何東西**：常態下多一句警告等於雜訊，真的出事時就沒人看了。

**補的路徑（不需要等工商憑證）**：`docs/specs/sources/mig41-samples/MIGV4.1範例檔/存證發票/`
底下已經有四份官方折讓範例（`G0401-ALW10000003`/`ALW10000013`、`G0501-ALW10000003`/`ALW10000013`），
F0401/F0501 當初就是靠這批 golden 測試做出來的，G 系列可用同樣做法。
工商憑證與驗測環境（wwwtest）卡的是**傳輸與實測**，不是 XML 產生器——
把 401 減項與 XML 產生整包掛在「等 Turnkey 憑證」底下是排序上的誤判。

順帶在同批補上的既有漏洞：`cancelInvoice` 的「僅作廢」路徑原本**沒有** `assertPeriodOpen`，
而 401 依 `invoice_date` 歸期且讀當下 `status`——等於能無聲改掉已關帳（可能已申報）期間的銷項數字。

**2026-07-30 更正**：上面那道鎖當初檢查的是**作廢日**，而作廢改動的是**發票日期所屬期間**的
銷項數字——「7 月的發票、8 月按下作廢」在 7 月已關帳時照樣過關，UI 向使用者保證的
「不會無聲改掉已關帳期間的銷項數字」是假的。現改為兩個日期都檢查（發票日期擋的是被改動的那一期、
作廢日擋的是作廢記錄要落在哪一期），且發票日期那道的訊息直接指出脫困路徑：改開退回／折讓單。

- 媒體檔檔名規則（實務慣稱以統編命名）未在要點原文逐字確認，目前用 `{統編}.txt`。
- 403（兼營）、404（特種）、彙加註記 A/分攤註記 B、媒體檔的退回折讓明細記錄未實作
  ——退回折讓的帳務面（2026-07-29）與 401 申報書減項（2026-08 B11）已完成，
  剩餘落差詳見上一節。**零稅率已於 2026-08（B12，migration 0028）接上**：
  課稅別在銷貨單／發票落地（附件五代號 1/2/3），零稅率銷售額依銷貨單取數
  （經海關出口免開統一發票，只看發票會漏）落申報書欄 22-25（代號 7/15/19/23）並計入
  銷售額總計；媒體檔零稅率銷項明細課稅別 2；兼營標記（company_profile.vat_mixed_business）
  時 generate401 直接 422 指路 403，不靜默產出錯類別的申報書。
- **零稅率仍未做的三塊**（B12 刻意的邊界，均在產出回應出聲）：
  ①得退稅限額／應退稅額（代號 113/114）不計算——其計算規則未經作業要點原文核對，
  一律填 0＝溢付稅額全額留抵，退稅以官方軟體匯入後的計算為準；
  ②媒體檔零稅率明細的**通關方式註記（第 81 碼）不填**——其代號值未經原文核對，
  用猜的比不填更糟，匯入官方軟體後依實際通關方式補正；
  ③附件「零稅率銷售額檔」（83 Bytes）未產出。
  另：零稅率發票 XML 的金額擺位（SalesAmount=0、金額走 ZeroTaxSalesAmount、
  TotalAmount=ZeroTaxSalesAmount）依 MIG 欄位語意實作，官方範例檔無零稅率案例可做 golden，
  最終以驗測環境上傳為準。
- **退回折讓在 401 申報書上的欄序**：已依 `return401.ts` 實作的附件六 112 欄版面接上
  （序 13/19、56/57/66/67，合計欄淨額連動）；該版面與官方申報軟體的最終核對
  仍以「媒體檔匯入驗收」為準（見第一條未決問題）。
- **退回折讓明細在附件五要用哪幾個格式代號？** 規則表第 2 條只核對過「銷項電子發票退回折讓」

  序 104「代理申報人登錄字號」的欄寬未逐字核對（實作以 ASCII＋寬鬆長度檢查）。
  兩者以官方申報軟體匯入驗收為準。

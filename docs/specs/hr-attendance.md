# HR 出勤模組

**狀態**：實作中（出勤本體 0039-0042、薪資 0044-0045 已落地）｜ **最後更新**：2026-08-26

> 本檔記錄出勤／薪資模組的功能邏輯與我們的取捨。
> 規模假設：數十人、排班制、全職＋部分工時混合、月薪＋時薪混合、部門主管簽核。
> **個資、公司識別資訊與實際金額一律不記錄。**

## 一、出勤系統要有的功能邏輯（按模組）

### 班別（排班管理 → 班別設定）
- 欄位：代碼（英數）、名稱、顏色、上班時間區間、**休息時間可多段**、工時自動計算、
  狀態、備註、**適用對象**
- **打卡歸屬日**：跨日班的核心解法——「從當天 HH:MM 後打卡，都歸屬同一天」的切點
  （固定班設在出勤規則、排班制設在班別上）
- 實例：PT 早/晚 4/6/8/9 小時班、跨日晚班 15:00~0:00

### 出勤規則（考勤管理 → 出勤規則設定）
一條規則＝（上班類型 × 打卡要求 × 異常政策）的組合，**帶啟用/停用日期**，
指派給一群員工。規則內含三個分頁：

1. **打卡規則**：
   - 上班類型：固定班（每週相同）vs 排班制（每月排班；需班別＋排班權限）
   - 彈性上下班：可早/晚 N 分鐘，**早到可早走、晚到需晚下**（附例：09-18 班可 07-11 進）
   - 打卡：需打卡/免打卡（老闆與主管常設免打卡）；休息要不要打卡
   - 打卡方式限定：WiFi（固定 IP）/GPS/QRcode/打卡機（多選）
   - **出勤異常管理**：遲到/早退/曠職/缺卡——按分鐘數區間設**扣薪級距**
     （依時薪比例或固定金額，多段可加）。要不要統計異常本身也是開關
2. **加班規則**：
   - 給付方式：加班費 vs 補休；可申請的日型：**平日/休息日/例假日/國定假日/排班人員休假日**
   - 事後申請可否、最小申請時數與單位（倍數）
   - 時數計算：申請 ≥4.5h 自動扣 30 分休息（可關）、扣不扣班別休息時間
   - 加班時數上限（有/無）、超時可否申請
   - **比對打卡紀錄**與否（以申請單為主 or 要打卡佐證）
   - 加班費/補休按日型分別設「以實際時數計 vs 採級距計算」（級距＝倍率表）
3. **忘打卡規則**：開放與否、申請期限限制、每月次數限制

### 假期（假期管理）
- **請假規則**（帶生效期間）內含假別清單：內建法定假別
  （特休/補休/事假/病假/婚假/喪假/家庭照顧假/生理假/產假/產檢假/陪產檢及陪產假/
  公假/公傷假/無薪病假/安胎假）＋自訂假別；內建的只能停用不能刪
- **每個假別的設定**（以特休為例，最完整）：
  - 給假制度：**曆年制（1/1）vs 週年制（依到職日）**
  - 截止與保留：年資未滿一年/滿一年分開設；可保留 N 個月或至次年 M 月底
  - **離職結算**：按在職天數比例；預給時數**追回政策**（不追回/追回全部）
  - 日標準工時（天→時換算基準）；最小申請單位；性別限制；**前置假別**（先請完 X 才能請 Y）
  - 薪資連動：是否結算、折算不休假代金（加項）、扣薪比例%（扣項）
  - **年資→給假天數對照表（0/0.5/1…25 年）留白給使用者填**——與我們稅法參數同一哲學
- **請假時數管理**：每人×每假別的年度額度帳（可用/已用/剩餘，精確到分——
  特休按到職日比例可給出 76 時 48 分這種數字）；年度給假批次；匯入/匯出
- **行事曆**：「人事行政局行事曆」作為一條帶生效期間的規則（國定假日/補班日來源）

### 申請與簽核（申請單管理）
- 三種申請單（請假/加班/忘打卡）各自設簽核流程：需要簽核/免簽核
- **多關卡簽核鏈**，關卡可指定「組織部門主管（當層）」等——主管掛在部門樹＋
  員工檔的「直屬主管」欄位上
- 請假單的「給假」與「准假」流程分開設

### 打卡方式（考勤管理 → 打卡方式）
- 四型：**GPS（地點＋範圍半徑公尺）**、WiFi（固定 IP）、QRcode、打卡機
- 每個地點可設適用對象（全體/特定員工）；「遠端打卡」＝無限制半徑開給特定員工

### 員工檔（人事管理 → 員工管理）
- 清單：編號/姓名/部門/職稱/登入信箱/**類型（全職/兼職/部分工時）**/**直屬主管**/
  到職日/帳號狀態/**職務狀態（在職/離職/待離職）**；批次匯入、標籤管理
- 單人檔 8 分頁：帳號及基本資料（身分證、生日、性別、國籍、婚姻、兵役、身障、
  聯絡資料、緊急聯絡人、LINE 綁定）/職務資料/出勤假別/**薪資資料（歷次紀錄）**/
  保險資料/所得稅資料/學習數據/學歷證照

### 薪酬（薪酬管理）
- **發薪群組**：計薪週期起迄＋發薪日，按群組跑（正職/各 PT 群組分開）
- **薪資科目表**（40+ 項）：每科目自帶屬性——納入平均時薪（請假扣款/加班費/
  不休假代金/投保薪資四個子旗標）、納入平均月薪、**應稅/免稅**、計算補充保費、
  計算職工福利金。應稅與免稅加班費、各種不休假代金（特休/補休/月休）、
  遲到早退曠職扣款（應稅/免稅）都是獨立科目
- **時薪計算公式**：按用途（請假扣款/加班費/不休假代金）各設公式
  （例：每月基準科目總額 ÷ 240）＋小數點規則
- **加班費免稅**：每月免稅上限有「時數上限」與「期間合計上限」兩種判定形狀（二選一），
  每種加班日型按時數區間標「免稅/計入每月判定/應稅」。
  **上限值一律使用者自填＋依據來源欄，系統不預設任何數字。**
- **投保單位**：勞保證號＋檢查碼、健保投保單位代碼＋業務組別、職災費率%（可多單位）
- **發薪作業**：按群組×月份建作業（結算區間、計算人數、發薪日、未發放/已發放狀態），
  另有補發作業與獎金作業

### 整合
- **「打卡資料串接」是加購功能**：透過 API 將打卡記錄同步至企業內部系統

## 三、法規紀律的適用（不變，觀察佐證）

市面上的出勤系統多半會內建一部分法規預設值（免稅上限、假別給薪比率之類）。
本專案維持更嚴的一致紀律：**所有勞基法/稅法數字
（倍率、上限、對照表、級距）一律使用者自填＋依據來源欄**，內建假別清單可以給
（名稱是結構不是數字），給薪比率與天數不預填。
出勤紀錄 append-only、補卡走申請不改原紀錄（勞基法出勤紀錄保存義務,動工時查條號）。

## 四、Golden sample 逐筆核對結論（2026-08-13，平行試跑完成第一輪）

> 以一家實際運作中公司的整月薪資與出勤資料做平行試跑逐筆核對而得。
> **來源檔案、公司識別、個資與實際金額一律不記錄**，這裡只記結構與公式。
> 內部恆等式全過；有異動者逐筆重算後全部解釋。

**已證實的公式**（按日資料逐筆核對）：
- 時薪 ＝（本薪＋伙食津貼）÷ 240，**先取到小數兩位再往下乘**
  （270.8333→270.83；不取整會在大量加班的員工身上差個位數）——伙食津貼計入時薪基底
- 加班級距**按日（按單）**套用，不是按月合計。四種日型的倍率設定形狀（數值一律使用者自填）：
  - 平日：按時數分段，各段各自的倍率（實際時數）
  - 休息日：按時數分三段，各段各自的倍率
  - 例假日：第一段**以固定時數計**（工作未滿仍按整段給付），之後按時數分段
  - 國定假日：與例假日同形
  ⚠️ **倍率、分段界線與固定時數全部由使用者自填**，系統只提供「按日型分段」這個結構。
  曾經有一版從樣本反推倍率而推錯（固定時數計造成的巧合）——**反推法定數字必錯，不要做**。
- 假別要有的**設定形狀**（數值一律使用者自填，系統不預設任何天數或比率）：
  每個假別各有「年度額度」「給薪比率」「是否結算/折算代金」「最小申請單位」；
  特休另有「剩餘折算」與「離職按在職比例結算」；補休有保留期限。
  少數假別的給薪比率會**隨另一個假別的已用額度分段**（例如同一年度內先後適用不同比率）。
  → 我們目前是單一 `payRatioPercent`，對既有樣本已足；
  上述「分段且與另一假別額度連動」的形狀是未來需求，先記錄不實作。
- 加班費可以只憑**核准的加班申請單**入帳（打卡檔沒有對應打卡的 4h 加班照樣給付）
  ——與我們「月彙總／算薪讀核准單」同一取數哲學。
- 請假扣款 ＝ 扣款時數 × 時薪 ×（1−給薪比率）；給薪比率是**使用者自填的設定值**。
  **扣款基數是請假時段對應的表定工時**（09:00~18:00 扣午休＝8h），
  不是匯出欄顯示的數字——那一欄與基數可能不一致（全日假顯示 7h、扣款按 8h）。
- 請假扣款的應稅/免稅拆分 ＝ 按 本薪:伙食津貼 比例分攤，**各自四捨五入後相加**
  （總額可能比未拆分多 1 元，是拆分進位的正常現象）。
- 早退扣款 ＝ 早退分鐘 × 時薪÷60（按分鐘比例，非級距）。

**已落地到我們引擎的**（migration 0042）：級距按單套用（原本按月合計是 bug，會多算）、
「以固定時數計」模式（fixed_minutes）、時薪取兩位小數。

### 第二輪（2026-08-13，整批匯入實跑發薪對總表）

> 整月按日資料灌進 docker 環境實跑發薪作業，逐人比對應發總額/應減總額/實發金額：
> 絕大多數到元全對，少數殘差全數解釋（見下）。
> 據此落地 0044（伙食津貼＋拆分＋遲到早退扣款）與 0045（補時制）。

第二輪新證實的規則（全部是**設定值與實務觀察**，不是法定斷言）：
- **遲到早退可能是「補時制」**：有些公司不罰晚到——當日配對打卡工時（扣休息重疊）
  補不滿表定工時的分鐘數才記為「早退」扣款（09:46 進 19:26 出＝不扣；
  10:20 就走＝480−80＝400 分）。已做成 attendance_settings.late_early_mode
  （'schedule' 預設＝對表定起訖；'shortfall'＝補時制），0045。
- **漏刷卡不自動扣**：晚班整月只有上班卡（無下班卡）照常計薪——
  補時制下無完整 in→out 配對的日子交人工，系統不猜（否則等於用「假設早退」罰漏卡）。
- **請假扣款基數＝請假時段長度−該班休息時長（不論重疊與否）**：
  14:00~18:00 的假扣 3 小時（休息 12-13 根本不在時段內也照扣）——所有假單金額全吻合。
  匯出檔的「請假時數」欄另有自己的算法（全日假可能顯示 7h 而基數是 8h），**不可拿來當基數**。
- **應免稅拆分＝兩側基底各自全精度算、各自四捨五入後相加**：
  兩側各自以全精度基底計算、各自四捨五入後相加；先取兩位小數再拆會差幾元。
  時薪取兩位小數僅適用加班費的合併時薪。
- 曠職扣款實務上也放在**「請假扣款(應稅/免稅)」欄**，不另設欄位。
- 匯出檔形狀：同人同日多列＝分段班（早班/晚班各一列，各自打卡）；
  表定 00:00~00:00 且表定工時 '--' 的列＝零工時佔位，要剔除。

已解釋的殘差（兩類）：
- **匯出時點漂移**：發薪當下匯出的出勤，與事後（補卡修正過）再匯的檔互相矛盾。
  教訓：**對數字必須用產生該結果當下的匯出**，不能事後補撈。
- **重度加班的捨入殘差**（約 0.013%）：窮舉十餘種捨入方案（按單/按月/floor/half-up/
  倍率順序）皆不完全吻合，需申請單層級的資料才能定案。我們按月合計取整。

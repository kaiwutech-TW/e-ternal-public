# 開始使用前：先備齊這些資料

> **這份只回答一件事：要準備什麼。**
> 「準備好之後照什麼順序做」在 [`SOP.md`](./SOP.md) 第一部分，安裝在 [`INSTALL.md`](./INSTALL.md)。
> 三份刻意不重複——**操作順序一律以 SOP 為準**，這裡只在每一項標出它對應 SOP 的哪一步。

大多數人卡住不是因為不會操作，是**坐下來才發現東西沒帶**：稅率沒查、字軌還沒申請、
期初餘額要回頭問記帳士。先照這份把資料湊齊，真正的設定大概一兩個小時就做得完。

**建議做法**：把第 2 節和第 5 節整段轉給你的記帳士——那兩節是你自己生不出來的。

---

## 0. 先做一個決定：切換時點

**你要從哪一天開始用這套系統記帳？**

這個決定會牽動後面所有的期初資料，先定它再往下走。常見的選法是月初或年初——
月中切換不是不行，只是期初餘額要抓到那一天，對帳會比較累。

決定之後寫下來：**切換日 = ____年____月____日**。第 5 節的每一筆餘額都是「這一天的餘額」。

---

## 1. 公司基本資料　→ SOP ①

| 要準備 | 去哪裡拿 | 沒有會怎樣 |
|---|---|---|
| 公司名稱、地址 | 營業登記資料 | — |
| 統一編號 | 同上 | 開發票、產 401 都會失敗 |
| **稅籍編號（9 碼）** | 國稅局核發的稅籍資料 | 產 401 會失敗 |
| **縣市別代號（1 碼）** | 同上 | 同上 |

> 稅籍編號與縣市別代號常被忽略——它們跟統編是不同的東西，申報用的是這兩個。

---

## 2. 你要自己查證的法定數字　→ SOP ③

**這一節最花時間，也最不能跳過。**

這套系統**不內建任何稅率、級距、倍率或上限，也不會告訴你數字是多少**。
不是還沒做，是刻意的設計：這些數字會變，而寫死的數字會在改版之前就悄悄算錯帳。
系統只提供結構與算術，答案由你填。

每一個數字都要附**依據來源**（你查到的法條、函釋或官方頁面，加上查詢日期）。
系統不驗證你填的內容——但那一欄是你日後被問到「這個數字哪來的」時唯一的憑據。

### 一定要準備

- **營業稅率**（含生效日期與依據來源）

### 要用到才準備

| 你要用的功能 | 要先查到的數字 |
|---|---|
| 扣繳（付款給個人：租金、專業服務費等） | 各扣繳類別的扣繳率、補充保費率 |
| 薪資與加班 | 加班費的倍率與時數分段、各假別的給薪比率與年度額度、加班費免稅的上限 |
| 勞健保 | 投保級距表、各項費率、負擔比例 |
| 兼營免稅或零稅率 | 適用範圍與比例計算方式 |

> **這些數字每年都可能變動。** 稅法參數表是「只增不改」的：法規變了是新增一列並接續生效日期，
> 不是覆寫舊的——因為舊年度必須算得回來（核定或更正可能兩三年後才來）。

---

## 3. 電子發票　→ SOP ④（要開發票才需要）

| 要準備 | 說明 |
|---|---|
| 字軌核准 | 先向主管機關完成申請與核准 |
| 期別、字軌（2 字母）、起號、迄號 | 核准後在財政部大平台取號，把這幾個值抄下來 |
| 憑證 / 平台帳號 | 若要自行傳輸，需要工商憑證與平台帳號；委由加值中心則依對方要求 |

> 實際申請流程與所需文件請以主管機關的公告為準，系統這邊只負責存你取到的號碼區間。
> 每家公司用**自己的憑證**傳輸，本系統不做集中代傳。

---

## 4. 主檔：客戶、供應商、商品　→ SOP ⑤

不必一次建齊，但**至少要有你第一張單會用到的那幾筆**，否則下拉選單是空的。

- **客戶／供應商**：名稱、統編（個人則另有身分證號欄，屬個資，僅財務與管理者看得到）、
  聯絡方式、付款條件
- **商品／服務**：品名、單位、售價、成本（有進銷貨才需要成本）

> 只做服務業、沒有庫存的話，商品可以只建「服務項目」，不必碰庫存那一段。

---

## 5. 期初餘額　→ SOP ⑥（最容易被低估的一節）

這是「切換日當天，帳上各科目是多少」。**建議直接請記帳士提供切換日的試算表**，
再照下面對應進來。

| 要準備 | 明細到什麼程度 |
|---|---|
| 現金、銀行存款 | 每個帳戶各自的餘額 |
| **未收的帳款** | **逐筆**：哪個客戶、哪張單、多少錢（不能只給總額，否則沖帳對不起來） |
| **未付的帳款** | 同上，逐筆 |
| 存貨 | 每個品項的數量與單位成本 |
| 固定資產 | 每項的取得成本、取得日、已提折舊、耐用年數 |
| 其他科目餘額 | 從試算表抄 |

> 應收應付**一定要逐筆**：之後收款時是勾對某一張單，只有總額的話勾不了。

---

## 6. 人員與帳號　→ SOP ⑦

先想好**誰要用、各自看得到什麼**。角色與權限對照表在 SOP ⑦，這裡只提兩個容易踩的：

- 要**報銷**的人，帳號必須連結到員工主檔，否則送件會被擋。
- 總經理角色是唯讀的（報銷除外）——如果那個人也要開單，給他別的角色。

準備：每個人的姓名、Email 或帳號名、要給的角色。

---

## 7. HR 與薪資　→（要用才需要）

| 要準備 | 說明 |
|---|---|
| 員工基本資料 | 姓名、到職日、部門、直屬主管（簽核鏈要用） |
| 部門結構 | 誰簽誰的假 |
| 班別與排班 | 上下班時間、休息時段、跨日班的歸屬日切點 |
| 薪資結構 | 每個人的薪資項目與金額 |
| 投保資料 | 投保單位編號、各人的投保級距 |
| 行事曆 | 國定假日與補班日（自己匯入或手填） |

> 倍率、級距、免稅上限這些**數字**在第 2 節，這裡只列「人與制度」的部分。

---

## 8. 公網部署才需要　→ SOP ⑧

只在內網用可以先跳過。要放上公網的話，安裝時就得決定（見 [`INSTALL.md`](./INSTALL.md) C 段）：

- `PII_KEY`：身分證號的加密金鑰。**未設定＝身分證號以明文存放**，
  系統會出聲提醒但不會擋你——這是刻意的（靜默降級比不加密更危險）。
- 備份加密密碼
- 二階段驗證要不要開

> 這幾個環境變數的共同紀律是「未設定＝維持既有形狀＋出聲提醒，絕不靜默降級」。
> 對照表在 [`deployment.md`](./deployment.md)。

---

## 一頁清單

開始之前，確認這些你都有了：

- [ ] 切換日訂好了
- [ ] 統編、稅籍編號、縣市別代號
- [ ] 營業稅率 ＋ 你查到的依據來源
- [ ] （要開發票）字軌核准、期別與號碼區間
- [ ] （要用薪資／扣繳）第 2 節那些數字，每一個都有依據來源
- [ ] 第一批客戶／供應商／商品
- [ ] 切換日的試算表，應收應付**逐筆**
- [ ] 每個人要給什麼角色
- [ ] （公網）PII_KEY、備份密碼決定好了

有一項打不了勾，就先去補那一項——比做到一半卡住再回頭便宜得多。

---

**卡住了？** 錯誤訊息看不懂是已知的體驗缺口（例如漏了 SOP ① 會在開發票時才炸，
而訊息不會告訴你「請先去設定頁」）。已知缺口誠實列在
[`gap-analysis-2608.md`](./gap-analysis-2608.md)。
